# Arm Clearance · 连续手臂与手部避碰

用于 Blender 动画的离线烘焙插件：联合调整双侧上臂、前臂和手腕，减少手臂、手掌、手指与身体或另一侧上肢的穿模，并尽量保留原动作。

Offline arm and hand collision correction for Blender animation, using whole-clip smooth corrections and reversible Action baking.

**当前版本：v0.2.7。** 下载见 [GitHub Release](https://github.com/BlankWX/arm-clearance/releases/tag/v0.2.7)。已有 Windows / Blender 5.2.2 LTS 的片段一致性与保存重开验证。插件元数据声明最低 Blender 4.4，但其他版本尚未完成兼容性验证。本项目仍处于早期版本，支持范围和复核限制见下文。

## 功能

- 以场景开始帧和结束帧为工作范围，联合求解整段修正，使用 C2 样条及速度、加速度约束减少抖动。
- 识别完整双臂的长静止段，在保持避碰修正的同时抑制静止时的缓慢旋转；[适用范围与实现](docs/STATIONARY.md)。
- 检测双臂与身体、左右上肢之间，以及手部与身体、对侧上肢和同侧手臂的相交。
- 手掌和手指表面参与检测；保留手指骨骼的原动画曲线，其空间位置会随上游手臂和手腕变化。
- 优先减少上臂姿态改动，允许前臂和手腕承担更多修正。保留权重和手腕平移软限制可调。
- 复制原 Action 生成烘焙结果，支持切换原动作、当前结果和上一版结果。
- 对真实变形网格进行整帧及半帧复核；未通过的完整烘焙仍会保留，并显示待复核状态。
- 播放使用普通关键帧，不依赖逐帧运行的插件处理器。插件本身无需联网或安装额外 Python 包。
- Windows 烘焙时默认显示系统控制台，输出当前阶段、优化组数、追加修复轮次、步骤和已用时间；可在高级设置中关闭自动显示。

## 安装

插件安装包为 **`arm_clearance-v0.2.7.zip`**；请从 [v0.2.7 Release](https://github.com/BlankWX/arm-clearance/releases/tag/v0.2.7) 下载并安装这个 ZIP。**`arm-clearance-v0.2.7-source.zip`** 及 GitHub 的源码归档用于开发，不是插件安装包。附件清单见 [发布说明](docs/RELEASE.md)。

1. 打开 Blender 的 **编辑 → 偏好设置 → 插件**。
2. 从右上角菜单选择 **从磁盘安装（Install from Disk）**，选择插件安装 ZIP。
3. 启用 **Arm Clearance · 连续手臂与手部避碰**。
4. 在 3D 视图按 `N`，打开 **手臂避碰** 侧栏。

已有旧版时，先结束正在运行的避碰任务，再安装更新并重启 Blender。开发者可以用 [构建脚本](tools/build_release.py) 生成安装 ZIP。

## 使用

1. 打开已有角色动画的工程，选中角色骨架，点击 **识别当前角色**。
2. 确认 **角色骨架、角色网格、检测材质**。自动识别会优先选择对应骨架下顶点最多的网格，需要自行核对。
3. 在时间轴设置场景的 **开始 / 结束帧**。工作范围至少三帧；建议先用一段较短动作验证，再扩大范围。
4. 在 **骨骼与高级设置** 中核对六根修正骨骼。默认名称如下。
5. 点击 **分析并烘焙场景范围**，等待优化、表面复核和必要的追加修复结束。Windows 默认打开系统控制台；也可点击侧栏的 **显示系统控制台** 查看日志。计算中避免编辑骨架；按 `Esc` 可取消，长时间计算期间需等待主线程返回后响应。
6. 用 **切换原动作 / 烘焙动作** 检查效果，按空格正常播放。详细报告在 Blender 文本编辑器中的 `ArmClearance_V2_Report_...` 文本数据块。
7. 满意后正常保存 `.blend`。插件不会自动把工程写入磁盘；保存工程后，原动作、完整烘焙结果和报告都会保留。

| 部位 | 左侧 | 右侧 | 修改通道 |
| --- | --- | --- | --- |
| 上臂 | `腕.L` | `腕.R` | 局部四元数旋转 |
| 前臂 | `ひじ.L` | `ひじ.R` | 局部四元数旋转 |
| 手腕 | `手首.L` | `手首.R` | 局部四元数旋转与位置 |

骨骼名称可以配置，但当前实现需要上臂 → 前臂 → 手腕的骨骼层级和可直接烘焙的变形骨骼，不是任意 IK 控制器绑定的一键适配器。

### “检测材质”如何区分身体和手臂

材质名称用于筛选**身体碰撞面的候选范围**，多个名称用英文逗号分隔并精确匹配。手臂、手部和身体通过蒙皮权重及骨骼层级分区，因此同一网格、同一材质上的身体和手臂可以区分。手部检测不按该材质列表裁剪。

默认材质名来自开发时的绑定习惯，其他模型应按实际材质修改。留空会使用所有材质的身体候选面，应核对头发、饰品等是否被纳入。

## 运行条件与边界

- 当前处理一个选定的蒙皮网格和一个活动 Action。未静音的 NLA 轨道需要先合并或烘焙。
- 六根目标骨骼使用四元数旋转模式；活动约束、相关驱动、目标曲线修改器或采样曲线应先烘焙为普通关键帧。
- 骨架对象需要正的均匀缩放。网格需要一个指向该骨架的活动 Armature 修改器，关闭 **保留体积（Preserve Volume）**；改变几何的其他修改器应先应用或禁用。
- 采用线性蒙皮采样；每顶点超过四个骨骼的剩余权重总和大于 `0.001` 时会拒绝截断。手腕主导权重的顶点和手部三角面需足够，过于简化或特殊权重的模型可能无法自动拟合。
- 不修改手指曲线，不修复同一只手内部的手指互穿。肩根、手腕等自然连接带会排除部分检测，离散采样也不等于连续时间的无相交证明。
- 范围内逐整数帧写入烘焙关键帧；`开始帧−1` 和 `结束帧+1` 用于过渡保护，这两个相邻一帧区间属于过渡区域。
- `needs_review` 表示完整结果已保留但复核未通过，`unverified` 表示已有完整烘焙检查点但复核未完成。取消或出错会恢复运行前的活动动作；首个完整烘焙形成前取消不会生成结果。

具体参数、取消和报告说明见 [使用补充](docs/USAGE.md)。

## v0.2.7 的累计更新

相对 v0.2.3，本版累计包含以下改进，保留默认参数、碰撞规则、C2 连续性和烘焙规则：

- **静止段保护**：六根目标骨骼旋转及双腕位置共同保持至少 16 帧时，共享连续避碰修正；主优化和追加修复均生效，并改善静止与运动交界的修正衔接。未检测到完整双臂静止区间的任务保留既有求解路径。
- **进度可见**：新增控制台按钮与默认显示开关，记录当前阶段、优化组数、步骤、线搜索和追加修复进度。同步计算内部仍可能暂时没有新日志，这不等同于界面始终可交互。
- **长动作矩阵卡点修复**：利用时间矩阵的五对角结构与样条紧支撑，避免五千多帧动作预计算时建立帧数平方的稠密矩阵；保留原求和次序和数值结果。
- **减少重复计算**：复用身体距离查询的临时缓冲与相同法线长度，缓存表面分区拓扑，压缩每个 BVH 的输入顶点；保留检测面、全局编号、默认采样密度和修复轮次。

## 验证与性能

### v0.2.7：静止保护，四个片段共 640 帧

2026-10-22 的功能验证覆盖 **1–400、1910–1989、3720–3799、5160–5239**，共 **640 个不同整数帧**。开头 1–360 帧烘焙姿态保持恒定；1–400 的 799 个整帧/半帧表面采样与冻结 v0.2.6 均无相交。

后三段不触发静止保护，目标查询轨迹、烘焙、半帧播放和完整表面报告与 v0.2.6 逐位一致；最终碰撞采样数仍为 **1、0、1**，非零命中保留 `needs_review`。静止约束会改变开头片段的最佳修正姿态，各项代理与动作指标并非全部改善。**本版没有重跑全片或完成全片原速视觉验收。** 详细取舍及合成回归见 [验证记录](docs/VALIDATION.md)。

### v0.2.6：三段共 240 帧的历史提速验证

v0.2.6 复用身体距离计算的临时缓冲与相同法线长度，并缓存表面分区拓扑、剔除每个 BVH 输入中未引用的顶点。保留检测面、全局编号、默认参数、整帧/半帧复核及原有修复轮次。

2026-10-22 的 v0.2.6 验证仅覆盖 **950–1029、2545–2624、3815–3894** 三段，各 80 帧，共 **240 个不同整数帧**。与冻结的 v0.2.5 对照，沿用默认 600 步主优化、最多三轮各 150 步追加修复；每轮表面复核含 159 个整数及半帧时刻。每版 3,809 次目标查询的完整输入/能量/梯度轨迹、全部修正数组、烘焙曲线及一至三阶修正差分均严格一致，完整报告仅总耗时不同。950–1029 帧结果还通过独立进程重开核验。

三段记录总耗时由 **330.447 秒降至 283.602 秒，约减少 14%**。另一次表面检测单次 AB 的片段耗时降低约 15.2%–39.2%。测量期间有 GUI 和准备任务并发，这些都是本机三段的观察，**不承诺全片提速比例**；v0.2.6 当时没有重跑 5772 帧。三段均保留原有 `needs_review`，一致性对照通过不表示碰撞复核通过。详见 [验证记录](docs/VALIDATION.md)。

### v0.2.5：5772 帧历史验证


v0.2.5 修复长动作在“预计算时间平滑矩阵”阶段的稠密计算瓶颈，保留原求和顺序及连续性约束。同规模 5772 帧、725 控制点的独立步骤基准约 **0.76 秒**；210 组矩阵及真实 174 帧求解对照的全部输出逐位一致。

2026-10-22 使用 v0.2.5 完成真实 **1–5772 帧**整段烘焙，四轮整帧及半帧复核均覆盖 11543 个时刻，检测命中依次为 **792 → 26 → 9 → 9**。最终状态为 **`needs_review`**，完整候选已保存并通过独立进程重开核验；检测命中不直接等于肉眼可见穿模或穿透深度。此次预计算阶段首轮日志计时 **2.094 秒**，缓存后约 1–2 毫秒，原卡点未复现。

全范围整数及半帧动作审计已完成：583 条非目标曲线（含 120 条手指旋转）精确保留。重点最坏及转向片段未见独立单帧突跳或逐帧交替回摆；仍有约 16 帧的平滑避让隆起后返回，以及 LINEAR 重采样带来的帧内节奏差异，尚不能宣称全片 GUI 原速播放无抖动。耗时和审计边界见 [验证记录](docs/VALIDATION.md)。

### v0.2.4 与 v0.2.3 的历史验证

v0.2.4 已通过控制台日志 8 项、操作器生命周期 7 项、真实求解器进度、七路径/十三次独立重开的持久化与安装 ZIP 回归。80 帧合成输入的全部求解输出与 v0.2.3 逐位一致。Windows 按钮和默认开关已通过注册检查；实际弹出窗口尚未人工界面验收。本次增加主线程日志，不引入后台线程；不会使同步计算自动变成可交互任务。单次计算内部可能暂时没有新输出，不提供持续心跳。

v0.2.3 在固定的 174 帧输入上，单次目标函数及梯度计算耗时降低约 **19%–36%**；本轮没有可直接比较的整段烘焙提速比例。完整重跑的关键帧曲线与 v0.2.2 相同，保存重开检查通过。

上述 v0.2.3 的 174 帧历史案例仍有两处离散复核记录，结果已完整保留。该历史案例的用户预览反馈良好；自动记录及其限制见 [验证说明](docs/VALIDATION.md)。不将个别案例的效果推断为所有绑定和动作均可消除穿模。
